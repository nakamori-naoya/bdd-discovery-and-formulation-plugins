# つむぎウォレットのお題に共通する条件

この条件は、つむぎウォレットの viewpoints.md のうち、業務知識で確かめられる観点を判断の型に書き直したもので、このお題のどの業務にも当てる。

### wallet-delay-is-not-duplication

重み: 3

要件は、遅れを許すことと、漏れや二重を許すことを別に書いている。

PASS：遅れを許す出来事についても、同じお金やポイントを二度動かさない決まりを業務の決まりとして残している。遅れや時刻の運用の値（何時までに、何時間ごとに）は業務の外へ置いている。

FAIL：遅れを許すことを理由に、二度動かさない決まりを落としている。または、運用の値を業務の決まりとして書いている。

### wallet-owner-gap

重み: 3

split.md は、マネーの残高とサポート担当の訂正の持ち主を決めておらず、一覧に無い業務が要ると判断したら止まって返すよう求めている。

PASS：担当の業務がそれらに頼るなら、自分の業務の決まりとして持ち主を引き受けず、止まって依頼元へ返したか、一覧に無い持ち主が要ることを依頼元へ返す事柄として書いている。頼らないなら、それらを定義していない。資料が無く止まったときは、報告と記録で、止まった理由がこの持ち主の空きであることを確かめる。

FAIL：持ち主の決まっていないものを、この資料が持ち主として定義している、または黙って前提にしている。
