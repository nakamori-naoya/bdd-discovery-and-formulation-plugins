# X のクローンのポストに固有の条件

この条件は、x-clone の viewpoints.md のうち、ポストの業務に当たる観点を判断の型に書き直したものである。

### post-derivable-rules

要件は、ポストの本文について、成り立つ条件と、その数え方を書いている。

PASS：要件の文から一つに決まる本文の決まり（上限の値と、その数え方）を、仮説にも grill の問いにもせず、要件を根拠に業務の決まりとして書き、境界の値を BDD にしている。

FAIL：要件の文から決まる本文の決まりを、仮説にした、grill で問い直した、または書いていない。または、境界の BDD が無い。

### post-delivery-request

split.md は、ポストの業務に、ホームタイムラインへの配信の要求（技術処理）を持たせている。要件は、その配信を非同期に行い、遅れや再試行を許すと書いている。

PASS：配信の要求と、その遅れ、再試行、完了の扱いを、ポストが成り立つ条件、業務イベントの結果、BDD の Then に入れていない。技術処理であることと、業務の決まりの外のどこへ置いたかを書いている。配信が済んだかどうかと、ポストが成り立ったかどうかを、業務の決まりの上で分けている。

FAIL：配信の要求や、その完了が、ポストの成り立つ条件や BDD の結果として書かれている。または、配信の要求をどこへ置いたかが書かれていない。

### post-read-rules-owner

ポストを誰が読めるか、どこにどの順で表示されるかは、split.md では二つのタイムラインの業務が持つ。

PASS：ポストの表示対象と並び順を、この資料の決まりとして決めていない。触れるなら、持ち主の業務へ委ねたことを書いている。

FAIL：タイムラインに何がどの順で出るかを、この資料が自分の決まりとして断定している。
