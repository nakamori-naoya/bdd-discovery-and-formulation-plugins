# X のクローンのユーザータイムラインに固有の条件

この条件は、x-clone の viewpoints.md のうち、ユーザータイムラインの業務に当たる観点を判断の型に書き直したものである。split.md は、この業務を、ほかの業務の事実を読むだけで、自分で書くものを持たない業務としている。

### read-only-business

PASS：業務を変える行い（コマンド）を持たないことと、後ろに立てる資料がクエリデータモデルだけであることが、資料から読み取れる。ほかの業務の語や業務イベントを定義し直さず、持ち主の資料の語として使っている。読むだけの業務でも、表示対象と並び順を、コマンドを持つ業務と同じ深さで書き、BDD にしている。

FAIL：コマンドやこの業務が持ち主の業務イベントを作っている。または、ほかの業務の語を定義し直している。または、表示対象か並び順が BDD になっていない。

### display-rules-from-requirements

PASS：要件の文から一つに決まる表示対象の条件（誰が誰の一覧を読めるか、どのポストが入るか）と並び順を、仮説にも grill の問いにもせず、要件を根拠に書いている。

FAIL：要件の文から決まる表示対象か並び順が欠けている、仮説にしている、または grill で問い直している。

### unknown-target-user

要件を読み、存在しない利用者の一覧を求められたときの扱いが要件で決まっているかを確かめる。

PASS：要件で決まっているなら、要件を根拠に書いている。決まっていないなら、拒むか空の一覧かを推測で断定せず、仮説か未決として、根拠と採らなかった案、または誰に聞けば決まるかを添えて書いている。

FAIL：要件で決まっていない扱いを、仮説の印なしに断定している。または、この場合の扱いに触れていない。

### cross-business-answers

split.md は、一覧を分けて返すときの続きの位置と、ポスト一件ごとに何を見せるかを、業務をまたいで同じ答えにすべき問いとして挙げ、答えを書いていない。

PASS：要件の文から答えが決まる問いは要件を根拠に書き、要件から決まらない問い（投稿者を何で示すかのような、プロフィールが対象外のために決まらない点）は、推測で断定せず、仮説か未決として印を付けている。

FAIL：要件から決まらない答えを、仮説の印なしに断定している。または、要件から決まる答えを仮説にしている。
