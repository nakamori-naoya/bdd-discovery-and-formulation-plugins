# ユーザーJourneyの構造

## 1本の中心

ユーザーJourneyは次の問いへ答える。

```text
どのユーザーが、何を達成したくて、どこから始まり、
どんなインタラクションを経て、何をもって最終地点へ到達するのか。
```

正本の冒頭の段落が、この問いへの答えを読み手の既知の語で文章として運ぶ。型の説明やメタ情報の一覧を冒頭に置かない。

目的が異なる場合は別の資料にする。途中で協働する役割が増えても、主たるユーザーの目的を入れ替えない。

## 確定しておく枠

- ユーザー: 目的を持って始める役割
- 目的: 最終的に実現したいこと
- 開始地点: 最初の働きかけより前に成立している状態
- 最終地点: ストーリーが終了したと判断できる状態
- 完了条件: 主たるユーザーが、自分の目的が満たされたと観測できる条件

どれか一つでも根拠から決まらなければ、場面を書き始めず不足項目と確認相手を返す。

## 場面の連なり

1つの場面は、前の場面から受け取る状態、行う役割、1つの主要な働きかけ、観測できる応答、次へ渡す状態を持つ。

ここでいう状態はJourney上の接続を説明する状態であり、DBの値、内部flag、論理上の対象化だけを指さない。主たるユーザーに見えない内部状態を接続に用いるときは、それだけで場面を完了させず、ユーザーが見えること、知らされること、または次にできることへ接続する。

最初の場面の前提は開始地点から来る。最後の場面の結果は最終地点と完了条件を満たす。中間の場面では、前の結果が次の前提へどう接続するかを`接続:`として明示する。

場面数に上限はない。ただし、目的達成と関係しない枝は入れない。既知の分岐は、どの場面から分かれ、最終地点へ戻るのか、別の終了になるのかを示す。

## 未決の扱い

接続、役割、応答、完了条件を確認できなければ、もっともらしい内容で補わない。未決事項と確認先を資料に残す。
