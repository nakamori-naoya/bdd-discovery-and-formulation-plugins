# 論理構造を固定してRDB物理設計へ写す判断規律

`design-physical`で同じagentが適用する。対象製品と版は入力`database_product`と`database_version`で受け取る。

- 入力は更新済みの論理モデル一つに固定し、テーブル、列、業務上のキー・関係・制約を物理都合で増減・再編しない。必要を見つけたら論理設計へ戻す。
- 業務で典型的かつ重要なReadごとに、対象、絞り込み、結合、並び順、鮮度、想定件数を記し、indexと性能判断の根拠にする。
- 論理設計の並行実行保証を、対象RDB・版での分離レベル、制約、ロック、競合時の中断・再試行へ写す。分離レベル名だけで完了にしない。
- 型、制約、index、時間表現、生成列、範囲、transaction機能は、対象版の公式資料または対象版の実機で確認できたものだけを採用する。current版、記憶、別製品の類似機能を根拠にしない。
- 論理テーブル定義と論理BDDを物理資料へ複製しない。入力論理資料を一つ示し、物理制約、型、index、分離レベル、配置、容量・性能・運用だけを書く。
- NULLは論理設計で許した箇所だけに使う。indexには対応するReadまたは制約と測定根拠を持たせ、複合indexは列順の理由を書く。
