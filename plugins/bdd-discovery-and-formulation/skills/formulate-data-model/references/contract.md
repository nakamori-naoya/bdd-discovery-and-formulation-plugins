# 論理データモデル定式化の工程間契約

入力は、対応する業務知識と、BDD・論理テーブル定義を持つ既存の`rdb-logical-data-modeling`資料である。

反証で確認された変更は、BDD、記録する事実、論理テーブル、列、業務制約へ双方向に戻す。BDDだけ、または表定義だけを変えて完了にしない。

更新先は既存の論理データモデル資料と同じ実体である。新しい論理資料を作らず、別pathへ複製しない。

Read、index、物理型、DBMS機能、分離レベル、partition、配置、容量・運用は成果物へ入れない。それらは論理上の意味または不変条件を変える場合だけ論理側の再検討事項となり、実現方式だけを変える場合は物理設計へ渡す。
