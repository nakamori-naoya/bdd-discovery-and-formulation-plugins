# BDDの入力根拠

BDDの発見と定式化で業務事実の根拠にできるのは、次の3つだけである。

1. 現在の依頼で利用者が述べた内容
2. 利用者が入力として明示した既存資料
3. grillで厳選して問い、利用者が確認した決定

業務用語、業務イベント、業務概念を、一般知識、もっともらしい例、referenceの例示から補完しない。表記を整える場合も意味を増やさず、元の語との対応を失わせない。QA観点やGiven・When・Thenなどの枠組みは問いを作るために使えるが、その問いに含めた仮説を業務事実として扱わない。

入力だけでは決められない、不明である、または深掘りが必要な論点のうち、成果を左右するものをgrill工程で厳選して利用者へ確認する（問う数の上限と対話の作法はgrillの公開契約に従う）。確認済みの回答は確定事項、それ以外の論点は推奨を添えた仮説または未決として、区別を保って`grounded_input`に渡す。止まるか進むかは、呼び出した公開入口の停止条件が決める。仮説で進むときは、仮説に依存する箇所に仮説であることと根拠を明示し、問いを回答責任者つきの未決へ残す。事実と書けるのは3つの根拠のどれかに辿れるものだけである。

成果物へ採用する各用語・イベント・概念は、3つの根拠のどれから得たかを辿れる状態にする。出所を示せないものは採用しない。
