# 記録すべき事実のシナリオ

**手法が何であれ、これだけは共通である。** 正規化中心でも、事実の記録中心でも、分析用でも、**「何を記録しないと業務が回らないか」が先**にある。

## なぜ手法より先か

**保存の形から入ると、記録の必要を誰も説明できないまま構造だけが残る。** 数年後に「この項目は何のために在るのか」と聞かれて答えられないものは、たいていここを飛ばして作られている。

**手法は「どう配置するか」を決めるだけである。** 何を記録するかは、手法では決まらない。

## 1件の形

| 項目 | 何を書くか | 空にできない理由 |
|---|---|---|
| **モデル要素** | どの要素の話か | どこへ置くかが決まらない |
| **記録する事実** | 何を残すのか。業務語で | 何を記録するか無いなら、そもそも記録ではない |
| **記録しないと困ること** | 残さないと業務の何が回らなくなるか | **ここが書けない要素は、手法が何であれ要らない** |
| **必要とする人** | その記録を誰が必要とするか | 誰も必要としない記録は、作った人だけの都合 |
| **出所** | どの業務の事実・どの具体例から来たか | 辿れない記録は、後から覆せない |
| 確からしさ | 確認済み・仮置き・未確認 | 確かめていないものを確定として扱わせない |

## 「記録しないと困ること」の良し悪し

| 良い | 悪い | なぜ |
|---|---|---|
| 取消の申し出があったとき、誰がいつ承諾したかを示せないと争いになる | 承諾を保存する必要があるから | 言い換えただけで、困りごとが無い |
| 締切後の変更を拒む根拠が、締切時刻を残さないと示せない | 締切管理のため | 何がどう困るのかが無い |
| 月末の精算で、どの単価が適用されたかを再現できないと請求できない | 履歴が必要 | 誰の何のための履歴か不明 |

**「〜のため」で終わる説明は、たいてい説明になっていない。** 記録が無かったときに**誰が何をできなくなるか**まで書く。

## よくある落ち方

| 落ち方 | 何が起きるか |
|---|---|
| 画面に出す項目を、そのまま記録項目にする | 画面を変えるたびにモデルが揺れる |
| 「あとで要るかもしれない」で残す | 誰も使わない記録が増え、正しさを誰も保証しなくなる |
| 業務の事実ではなく、処理の途中経過を残す | 作りを変えると意味が消える |
| 記録の必要を、実装の都合（検索が速い等）で説明する | 実装が変わると根拠ごと消える |

## モデルとの突き合わせ

**両側から見る。**

- モデルにあるのに、記録すべき事実として説明されていない要素 → **要らないか、説明が抜けている**
- 記録すると決めたのに、モデルに置き場が無いもの → **落ちている**

片側だけを見ると、増えることはあっても減らない。
