# map-user-journey（目的達成の連続性をmapにする）

読み終えると、根拠づけられた入力から、1人の主たるユーザー、1つの目的、開始地点、観測可能な完了、複数の意味ある場面、状態の受け渡し、既知の分岐を持つJourney mapを、同じ文脈に保持できる。mapは後続でBDDへ写すための判断結果であり、それ自体を正本として保存しない。ユースケース、UX Journey map、ドメインルール、データモデル、UIフロー、テスト仕様はこのskillの外である。

## 入力

根拠づけられた入力（利用者の発言、明示された資料、確認済みの決定と未決の区別）と、役割×目的の一覧から選ばれた今回の1本を、この判断規律を適用するagentが同じ文脈に保持していること。既存のJourney BDDを再判定する場合は、その本文も入力である。

## 判断基準

[User Journey](references/user-journey.md)と[何ではないか](references/journey-boundary.md)を読んでから判定する。

| 観察対象 | 述語 | 行動 |
|---|---|---|
| 読み手の問い | 複数の場面が状態を受け渡し、ユーザーの目的が観測可能な完了へ進む連続性を問うている | Journeyにする。対象システム一つでも、時間をまたぐ全体の連続性を問うならJourneyにできる |
| 目的 | 機能利用そのものではなく、ユーザーが実現したい結果である | 進む。機能利用が目的なら非該当として理由を返す |
| 意味ある場面 | 二つ以上ある | 進む。一つならJourneyへ広げず、単一の責任または振る舞いとして返す |
| 対象システム一つの責任を問う | そうである | ユースケース候補として返す |
| 感情と接点の改善を問う | そうである | UX Journey map候補として返す |
| 業務判断を問う / 保存事実を問う | そうである | 業務知識 / データモデルへ送る |
| どちらの問いか | 入力から決まる | 進む。決まらなければ、答えで分岐が一つに決まる一問を返して止まる |
| 場面や分岐の違い | この違いが起きたとき、主たるユーザーは何を見て気づく | 気づくなら場面または分岐にする。気づかないなら書かず、断り書きも書かない |
| 行う役割 | 主たるユーザーか、主たるユーザーとやり取りする人である | 役割にする。システム上の主体は主たるユーザーが観測する結果へ畳む |
| 目的または完了条件 | 一つである | 進む。二つあるなら目的ごとに別mapにし、今回の1本以外は候補として返す |
| 前の場面の次状態と次の場面の直前状態 | 後者が前者から成立する理由を説明できる | 接続として書く。説明できなければ推測で補わず未決にする |

## 手順

1. [Journey mapの構造](references/journey-map-structure.md)を読み、利用者の発言、明示された資料、確認済みの決定だけを根拠に、ユーザー、目的、開始地点、最終地点、完了条件を一件ずつ定める。どれか一つが根拠から決まらなければ場面を書かず、不足項目と確認相手を返す。
2. [場面と状態の受け渡し](references/scenes-and-continuity.md)を読み、各場面へ直前の状態、行う役割、一つの主要な働きかけ、観測できる応答、次の状態、次への接続を書く。
3. 中断、再開、分岐、役割移譲が入力にあれば[分岐・中断・再開](references/branches-and-resumption.md)を読み、分かれる場面、再開に必要な状態、完了へ戻るか別の終了になるかを書く。正常な一本道へ隠さない。
4. [Journeyと他の正本の関係](references/journey-concept-map.md)を読み、他の正本へ送る事項がmapへ混ざっていないことを確かめる。混ざっていれば外し、送り先（業務知識 / 非機能要件 / 別Journey / 実現方式）を作業記録に残す。

## 停止条件

- Journeyの問いではない。非該当理由と次に作るべき成果物を返す
- ユーザー、目的、開始地点、最終地点、完了条件のどれかが根拠から決まらない
- 意味ある場面が二つ未満

## 出力

- Journey map（ユーザー、目的、開始地点、最終地点、完了条件、場面の連なり、既知の分岐、中断と再開、役割移譲）。同じagentの文脈に保持する
- 何ではないと判定して除外したものと、その送り先
- 未決と、何が分かれば確定できるか
