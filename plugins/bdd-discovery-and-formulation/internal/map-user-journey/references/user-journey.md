# User Journeyとは何か

User Journeyは、1人の主たるユーザーが1つの目的を持った開始状態から、その目的が満たされたと観測できる状態までに通る、意味のある場面と状態の受け渡しである。

中心は製品機能の順番ではなく、ユーザーの目的が最後までつながっていることである。場面は、ユーザーまたは協働する役割にとって意味のある状態変化が起きる単位で分ける。システム、組織、担当者、時間をまたいでも、主たるユーザーと目的を入れ替えない。

## User Journeyである条件

次をすべて満たす。

1. 目的を持つ主たるユーザーが一人に定まる
2. 機能利用ではなく、ユーザーが実現したい目的が一つに定まる
3. 最初の働きかけより前の開始状態が分かる
4. 目的達成を観測できる完了条件が分かる
5. 意味のある場面が二つ以上ある
6. 各場面の結果が次の場面の状態へ受け渡される
7. 読み手の問いが、個別の責任や業務判断ではなく目的達成全体の連続性にある

## 典型例

出張者が条件を決め、候補を選び、上長の承認を受け、予約が成立し、必要情報を受け取るまでを扱う。複数の役割と責任境界をまたいでも「出張に必要な手配を完了する」という目的が一つで、各場面の状態が次へ渡るためUser Journeyである。

## 条件を一つ変えた境界例

同じ予約システム内に複数の場面がある場合でも、時間をまたぐ目的達成全体の連続性を問うならUser Journeyである。問いを「予約システムは予約者へ何を保証するか」に変えた場合は、対象システムの責任を記述するユースケースへ切り替える。
