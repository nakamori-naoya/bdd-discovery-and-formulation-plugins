# User Journeyは何ではないか

User Journeyである条件と似て非なる成果物を同時に比べ、名前ではなく読み手の問いで分ける。

## ユースケースではない

ユースケースは、選んだ対象システムまたは対象組織が、主アクターの目的に対して果たす振る舞いの責任を記述する。事前条件、開始契機、基本成功、代替・失敗、成功時保証を、対象境界と外部アクターの相互作用として明らかにする。

対象システム一つの責任が問いなら、場面数が多くてもUser Journeyへ広げない。User Journeyは、複数の責任境界や時間をまたぐ目的達成全体の連続性が問いである場合に使う。対象を組織全体へ広げたユースケースとは重なり得るため、形式ではなく読み手が決めたいことを優先する。

## UX Journey mapではない

UX Journey mapは、接点、感情、痛み、期待、改善機会を理解するために使う。今回のUser Journeyは、目的、状態変化、場面接続だけを扱う。感情や接点の改善が中心なら、このskillでは保存しない。

## ドメインではない

ドメインは、事業で何を正しいと判断するか、誰が判断できるか、どの状態遷移を許すかを扱う。個別の業務判断が問いならdomain-ruleへ送る。Journeyは既存ルールを根拠として参照できるが、新しいルールを確定しない。

## データモデルではない

データモデルは、時間を越えて残す事実、関係、制約、履歴を扱う。Journeyは「承認された状態が予約へ渡る」という意味上の接続を扱うが、承認をどの構造で保存するかは決めない。

## UIフローとテスト仕様ではない

UIフローは操作と画面遷移、テスト仕様は実行対象、手段、環境、期待結果の検証を扱う。Journeyの場面は、利用者または関係者から観測できる意味ある変化であり、クリック順や自動実行の手順ではない。

## 明確な反例

「検索欄へ語を入力し、検索ボタンを押し、一覧から一件をクリックする」は操作列であり、目的、開始状態、観測可能な完了がないためUser Journeyではない。
