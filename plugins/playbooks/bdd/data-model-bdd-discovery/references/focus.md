# データモデリングの振る舞い発見で見るもの

このplaybookは、業務シナリオと業務イベントから、何を時間を越えて残す必要があるかを発見する。関心は作成・更新・削除にあり、検索や表示の便利さは論理設計の判断へ持ち込まない。

良い問いは「この出来事によって初めて成立した事実は何か」「現在状態を変えるだけか、過去の事実を追加で残すか」「取消や訂正の後も説明に必要な履歴は何か」「業務上の失効と物理削除はいつ一致するか」「同じ事前状態から同時に進んだとき、どの記録結果を許してはいけないか」である。

一つのシナリオには一つの業務イベントと一つの永続化上の変化を置く。作成・更新・削除はSQL命令ではなく、事実の成立、現在状態の変化、保持理由が尽きた記録の削除として扱う。Read、索引、物理型、分離レベル、API、DTO、ORMはこの発見では扱わない。

論理モデルを作る前に全シナリオを検査する。資料化では`rdb-logical-data-modeling`テンプレートを使い、各BDDのBeforeとAfterへ全論理テーブルを同じ順序で記載する。0件と変更なしを省略しない。
