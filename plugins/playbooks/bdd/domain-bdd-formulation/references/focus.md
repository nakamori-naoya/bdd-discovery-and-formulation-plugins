# ドメインのシナリオで確かめるもの

このplaybookは、既存資料でコアドメインと線引きされた業務の状態、事実、条件からどの判断と次状態が導かれるかを反証し、理解を深化させる。支援・汎用は扱わない。確認済みの境界を説明するために必要な例だけを、既存資料へ戻す。

Givenには判断前に成立している業務上の事実、Whenには判断を必要にした業務イベント一つ、Thenには観測できる判断・結果・次状態を書く。画面、API、保存、コードの語は使わない。

アクターの要求から応答までを説明することや、複数の接点を越えて価値へ届くことを同じシナリオへ混ぜない。必要なら目的の異なるplaybookで別のシナリオにする。

```gherkin
Scenario: 利用開始前の予約は予約者が取り消せる
  Given 利用開始前の確定予約がある
  And 予約者本人の予約である
  When 予約者が予約を取り消す
  Then 予約は取消予約になる
  And 会議室は同じ時間帯に予約できる状態になる
  # クロージャ: このシナリオの Given に書かれていない業務条件は、成立・結果に影響しない。
```
