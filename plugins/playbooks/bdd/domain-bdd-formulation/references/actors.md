# 登場人物と情報差

次のいずれかに当てはまるシナリオへ適用する。

- 意思を持つ主体が2つ以上登場する
- 申告、問い合わせ、回答、同意、拒否などの発話がある
- 同じ事実について、主体ごとに知っている内容が違う

## 主語・対象・相手を省略しない

各stepで「誰が」「何を」「誰に」を明示する。主体が入れ替わる会話では、代名詞や直前の文脈へ頼らない。

```gherkin
When 顧客が、氏名「山田 花子」と電話番号「08012345678」を担当者に伝え直す
```

## 値を知る側と知らない側

そのstepの主語が値を提供・主張する情報源なら、実際の値を書く。「正しい値」「適切な情報」で済ませると、読み手が同じ状況を再現できない。

まだ値を知らない側が問い合わせる場面では、評価語のままでよい。

```gherkin
When 担当者が、登録済みのメールアドレスを顧客に尋ねる
And 顧客が、メールアドレス「hanako.yamada@example.jp」を担当者に伝える
```

後続の行為を正当化する場合は、「担当者は登録済みのメールアドレスをまだ確認していない」のように、知らない状態もGivenへ書く。知識差がThenに影響しないなら書かない。

## 事実の出所を区別する

自己申告とシステムの記録は別の事実である。同じ事柄について複数の出所があり、その一致・不一致がThenへ効く場合は、出所ごとに1行で書く。

```gherkin
Given 顧客は自己申告で、氏名「山田 花子」と名乗っている
And 会員台帳の登録氏名は「山田 花子」である
```

出所がThenの合否に影響しない場合は、由来を機械的に付け足さない。

## 発話を逐語で書く条件

発話の文言そのものが合否を分ける場合だけ、鉤括弧で逐語引用する。同意、拒否、撤回など、その言葉が業務上の成立要件になる意思表示が該当する。

```gherkin
When 顧客が「はい、同意します」と担当者に回答する
```

定型的な報告や通知は要約する。逐語にしても合否が変わらない文を引用すると、文言変更のたびにシナリオが壊れる。
