# E2E BDD documentation 実行指示書

## 背景と目的

このplaybookは、目的を持つユーザーが開始地点から複数のインタラクションを経て、目的が満たされた最終地点へ到達するまでを、一続きのBDDストーリーとして共通理解にする。個々の決まりやデータ構造の網羅ではなく、目的達成までの因果を端から端まで説明できることを優先する。

## 前提

- 1本の資料は1人の主たるユーザーと1つの目的を中心にする。
- 目的達成に必要な場面数を先に制限しない。
- 利用者の発言、明示された資料、確認済みの決定だけを確定事項にする。
- domain-ruleとdata modelは参照できるが、このplaybookから変更しない。
- E2Eテストの実行、環境、証拠収集は対象にしない。

## skillを実行するときの指示

### grill

誰が、何を達成したいのか、どの状態から始まり、何をもって最終地点へ到達したと判断するかを先に確かめる。その後、途中で必要な役割、各場面の働きかけと応答、前後の場面をつなぐ状態、既知の分岐を1問ずつ確認する。画面やAPIの操作方法、保存方法、テスト方法を質問しない。

### writing-rules

シナリオ全体を短くするために必要な場面を削らない。目的と最終地点を冒頭に置き、場面を順番に並べ、各場面の結果から次の場面の前提へ自然に読み進められるようにする。説明文で接続をごまかさず、Given / When / Thenへ具体的な状態、働きかけ、応答を書く。

### write-doc

`e2e-bdd-scenarios`の型を使い、ユーザーの目的、開始地点、最終地点、完了条件、場面の連なり、既知の分岐、未決を1本へ保存する。domain-rule、data model、実装説明、テスト実行記録を混ぜない。
