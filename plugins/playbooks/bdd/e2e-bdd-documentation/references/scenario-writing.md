# 場面のBDD

## ストーリー全体と場面を分ける

E2Eストーリー全体には複数のインタラクションがある。1つの巨大なGiven / When / Thenへ押し込まず、順番を持つ場面へ分ける。

```gherkin
### 場面 1: 目的が分かる名前

Given 開始地点または前の場面から受け取った状態
When 役割が行う主要な働きかけ
Then 役割が観測できる応答
And 次の場面へ渡る状態

接続: 次の場面は、この結果を前提として始まる
```

各場面は1つの主要な働きかけを持つ。ストーリー全体では場面ごとにWhen / Thenが繰り返されるため、長いインタラクティブな流れを表現できる。

## 書く高さ

- ユーザーや協働役割から観測できる振る舞いを書く。
- UI部品、URL、API、通信形式、class、DB構造を書かない。
- test runner、実行環境、試行回数、証拠、CI、flaky判定を書かない。
- 業務ルールを新しく決めず、既存資料または確認済みの決定を根拠にする。
- データの保存方法や論理構造を設計しない。

## 長さ

ストーリー全体の場面数とstep数は制限しない。長いこと自体を問題にせず、目的へ寄与しない場面、同じ結果を繰り返す場面、前後が接続しない場面を問題にする。
