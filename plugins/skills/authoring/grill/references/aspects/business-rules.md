# 詰める観点（業務の決まりを確定させる）

**業務そのものを確定させるときに使う。** 作りの都合は問わない。画面・保存・境界のやりとりを問うと、業務の人は答えられず、答えられる人は業務を知らない。

`.harness-plugins/grill.config.yml` の `aspects` に `business-rules` と書くと、この観点になる。

**上から順に降りる。** 上流が決まらないうちに下流を問うても、上流が変われば全部やり直しになる。

| 観点 | 何を確定させるか |
|---|---|
| **起きること** | どんな事実が、どの順で起きるか。誰も操作しなかったら何が起きるか |
| **言葉** | 現場が使っている語と、その意味。同じものの別名をどちらへ寄せるか |
| **担い手** | 誰の行いか。役割ごとに何を行えて、何を行えないか |
| **まとまり** | 1つのこととして扱われる範囲はどこまでか。どこで切れるか |
| **常に守られること** | 状態や操作によらず、いつでも破ってはならない決まり |
| **移り変わり** | 取りうる状態と、移れる先。移れない場合の業務上の理由。終わりはどこか |
| **境界値** | 0件・上限・期限当日・空・重複。それぞれ業務としてどう扱うか |
| **拒む理由** | 拒むのはどんなときか。なぜ拒むのか（業務上の根拠） |
| **同時に起きたとき** | ぶつかる行いのどちらが通るか。順番が結果を変えるか |
| **時間** | 過去へ遡れるか。未来を予約できるか。訂正の跡は残すか |
| **後始末** | 取消・訂正・払戻はあるか。取り消した後、何が戻り、何が戻らないか |
| **波及** | この決まりが、隣の業務のどこへ効くか |

**「後始末」と「同時に起きたとき」は、聞かなければ絶対に出てこない。** 現場は普通に回っている流れしか語らない。ここに業務知識のいちばん濃い部分が埋まっている。

**各観点で「曖昧」または「未決」が見つかったら、1問にする。** 見つからなければ次の観点へ降りる。

## 業務の話でなくなったら止める

問いが次のどれかを聞いていたら、それは業務ではなく作りを問うている。**問いを立て直す。**

- どこへ保存するか、どんな形で持つか
- どの画面のどの操作か
- どういう順で処理するか
- 何という記号で返すか

**問い直し方**: 「それが起きたとき、業務としては何がどうなっているのですか」。
