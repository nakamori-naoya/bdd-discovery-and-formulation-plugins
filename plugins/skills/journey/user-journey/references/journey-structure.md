# Journeyの構造

## 境界判断

`中心の問い`は読み手がこのmapで決めたいこと、`Journeyとして扱う理由`はUser Journeyである七条件のどれを満たすか、`Journeyに含めない問い`は似て非なる成果物へ送る問いである。三つを同じ場所に置き、「何か」だけでなく「何ではないか」を成果物に残す。

## ユーザー

目的を持ってJourneyを始め、その達成可否の影響を受ける主たる役割である。途中で協働する役割を主たるユーザーへ入れ替えない。

## 目的

Journeyが終わったときにユーザーが実現したい結果である。「検索機能を使う」のような手段ではなく、「希望に合う候補を見つける」のような結果で書く。

## 開始地点

最初の働きかけより前に成立している、目的に関係する状態である。最初の操作を開始地点にしない。

## 最終地点と完了条件

最終地点はJourneyが終了した後の状態、完了条件は目的が満たされたと観測できる判定条件である。「処理が成功した」のように観測者と意味が不明な表現を使わない。

## 場面

主たるユーザーまたは協働役割にとって意味のある状態変化が一つ起きる単位である。単一の操作や内部処理では分けない。二つの場面を取り除いても目的達成の説明が変わらないなら、その場面はJourneyに要らない。
