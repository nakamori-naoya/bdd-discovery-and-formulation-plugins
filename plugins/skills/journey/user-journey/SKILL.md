# map-user-journey

**これは、ユーザーの目的達成が時間と責任境界を越えてどうつながるかをmapにするskillである。** 根拠づけられた入力を受け、1人の主たるユーザー、1つの目的、開始地点、観測可能な完了、複数の意味ある場面、状態の受け渡しを持つ検査済みJourney mapを返す。

**これは、ユースケース、UX Journey map、ドメインルール、データモデル、UIフロー、BDD、テスト仕様ではない。** 対象システムの責任、感情と接点、個別の業務判断、保存する事実、操作順、Given / When / Then、実行方法は決めない。

## 0. 配布rootを検証する

```bash
PLUGIN_ROOT="${CLAUDE_PLUGIN_ROOT:-/absolute/path/to/this/plugin}"
bash "${PLUGIN_ROOT}/scripts/prepare.sh" --root-only >/dev/null || exit 2
```

## 1. 何か／何ではないかを同じ条件で判定する

[User Journey](references/user-journey.md)と[何ではないか](references/boundary.md)を必ず読む。目的が機能利用そのものならJourneyにしない。意味のある場面が二つ未満ならJourneyに広げない。対象システム一つの責任を問う場合はユースケース候補、感情と接点の改善を問う場合はUX Journey map候補、業務判断を問う場合はdomain、保存事実を問う場合はdata modelとして、非該当理由と次に作るべき成果物を返して停止する。

複数の場面が状態を受け渡し、ユーザーの目的が観測可能な完了へ進む連続性を問う場合だけ次へ進む。対象システムが一つでも、時間をまたぐ全体の連続性を問うならJourneyにできる。どちらの問いか入力から決まらなければ、答えで分岐が一つに決まる一問を返して停止する。進む場合は、`中心の問い`、`Journeyとして扱う理由`、`Journeyに含めない問い`をmapへ一件ずつ残す。

## 2. Journeyの両端を決める

[Journeyの構造](references/journey-structure.md)を読む。利用者の発言、明示された資料、確認済みの決定だけを根拠に、ユーザー、目的、開始地点、最終地点、完了条件を一件ずつ定める。

目的または完了条件が二つある場合は混ぜず、目的ごとに別mapとする。どれか一つが根拠から決まらなければ場面を書かず、不足項目と確認相手を返して停止する。

## 3. 意味のある場面と接続を作る

[場面と状態の受け渡し](references/scenes-and-continuity.md)を読む。各場面へ、直前の状態、行う役割、一つの主要な働きかけ、観測できる応答、次の状態、次への接続を書く。前の場面の次状態と、次の場面の直前状態が意味上つながらなければ推測で補わず未決にする。

中断、再開、分岐、役割移譲が入力にある場合は[分岐・中断・再開](references/branches-and-resumption.md)を読む。正常な一本道へ隠さず、分かれる場面、再開に必要な状態、完了へ戻るか別の終了になるかを書く。

## 4. 検査して保存する

[概念の関係](references/concept-map.md)を読み、他の正本へ送る事項がJourney mapへ混ざっていないことを確かめる。本文を一時ファイルへ書き、次を実行する。

```bash
python3 "${PLUGIN_ROOT}/scripts/journey.py" write \
  --repo "$(pwd)" --slug <英数とハイフンの識別子> --file <journey-map.md>
```

既存fileがあれば上書きせず停止する。検査違反があれば保存せず、違反箇所、非該当先、不足情報を返す。

## 5. 報告する

- Journey mapの絶対パス
- ユーザー、目的、開始地点、完了条件、場面数
- 主要な状態の受け渡し、分岐、中断、再開
- 何ではないと判定して除外したものと、その送り先
- 未決と、何が分かれば確定できるか

Journey mapをBDDへ変換する作業、既存BDDを深化する作業へは進まない。
