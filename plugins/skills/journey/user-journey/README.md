# user-journey

1人の主たるユーザーが1つの目的を達成するまでについて、何がJourneyで何がJourneyでないかを判定し、開始、完了、意味のある場面、状態の受け渡しを検査済みmapとして保存する。

## 何を返すか

既定では`<repo>/bdd/discovery/user-journey/<slug>.md`へJourney mapを保存する。mapは次を持つ。

- ユーザー、目的、開始地点、最終地点、完了条件
- 中心の問い、Journeyとして扱う理由、Journeyに含めない問い
- 二つ以上の意味のある場面
- 各場面の直前状態、役割、働きかけ、観測できる応答、次状態、接続
- 既知の分岐と未決

## 何を返さないか

- 対象システム一つが果たす責任を記述するユースケース
- 感情、接点、不満、改善機会を中心にしたUX Journey map
- 個別の業務判断を正本化するdomain-rule
- 保存する事実と整合性を決めるdata model
- 画面手順、API仕様、テスト実行仕様
- Given / When / Thenを持つ最終BDD資料

## 使用例

典型例は、複数のシステムや人の役割をまたいで「出張に必要な手配を完了する」までの連続性を明らかにする依頼である。

非該当例は「予約システムが予約者へ何を保証するか」であり、対象システムの責任を問うためユースケース候補である。

境界例は一つのシステム内に複数場面がある場合である。問いが対象システムの責任ならユースケース、時間をまたぐ目的達成の連続性ならJourneyとして扱う。

概念境界は[User Journey](references/user-journey.md)と[何ではないか](references/boundary.md)を正本にする。
