# 手法: 正規化中心（関係モデル）

**同じ事実を2か所に持たない。** 事実を、それが依存する対象のところへ1つだけ置く。

## 先に決めること

1. **対象（何についての事実か）。** 事実ごとに「何を決めれば決まるか」を言う
2. **識別。** 業務上、何をもって同じものと判断するか
3. **多重度。** 1つに対していくつ在りうるか。0でよいか
4. **時間で変わるもの。** 変わるたびに上書きしてよいか、変わった事実を残すか

## 成果物として出すもの

- 業務上の条件と結果を示すBDDシナリオ
- 論理テーブルの一覧（`## 論理テーブル定義`の下で`### \`table_name\`（業務上の名前）`を見出しにする）
- 各論理テーブルの列（カラム名、制約、型、値域・意味）と、その事実が何に依存して決まるか
- 業務制約（`#### 業務制約: <名前>`）と、その根拠となるBDDシナリオ
- 対象どうしの関係と多重度
- 上書きしてよい事実と、履歴を残す事実の区別

この段階で論理テーブル、列、業務上のキーと制約を決める。物理設計はその構造を変えず、対象RDB上の型、物理制約、index、分離レベル、配置を加える。

## この手法が向くとき

- 業務の対象がはっきりしていて、事実の重複を避けたい
- 整合性の担保が最優先で、参照の形が安定している

## 向かないとき

- 「なぜ今こうなっているか」を頻繁に問われる（上書きで理由が消える）
- 見え方が業務ごとに大きく違い、1つの形へまとめると誰にも合わない

## 見直しの問い

- **その事実は、本当にその対象について決まるか。** 別の対象について決まる事実が紛れていないか
- 同じ事実が2か所に現れていないか。現れているなら、どちらが正本か
- 「無い」と「まだ分からない」を区別しなくてよいか
- 上書きしている事実のうち、後から理由を問われるものはどれか
