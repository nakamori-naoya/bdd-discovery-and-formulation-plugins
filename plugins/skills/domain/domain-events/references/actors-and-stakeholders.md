# アクターと利害関係者の関心を分けて捉える

**アクターは人名やシステム名ではなく、目的と責任を持って関わる役割である。** 直接操作する者だけを見ても、守るべき利害は見つからない。

## 実際の仕事で何を区別するか

アクターは、対象との相互作用において特定の目的、権限、責任を持つ役割である。同じ人が状況によって複数のアクターになり、複数の人や外部主体が同じアクターを担うことがある。

- 主アクター: 目的の達成を求め、相互作用を開始する役割
- 支援アクター: 目的達成に必要なサービスや情報を提供する役割
- 利害関係者: 結果から影響を受け、守るべき利害を持つ当事者。対象を直接操作するとは限らない

利害関係者の関心は、「誰の、どの便益、権利、義務、損失を守るか」を表す。アクター名を列挙するだけでは、成功時と失敗時に何を保証すべきか決まらない。

## 役割と利害の境界を見つける

まず、誰が目的達成を求めて業務を始めるかを見る。その人が主アクターである。判断に必要な情報や能力を提供する役割は支援アクターである。結果から利益または損失を受ける人は、直接操作しなくても利害関係者である。

人と役割を同一視しない。同じ担当者が申請者として始め、別の場面では承認者になるなら、権限と責任の異なる二つのアクターとして扱う。反対に、複数人が同じ責任と判断基準で交代して働くなら、一つの役割として捉えられる。

アクターと利害関係者の境界は、画面を操作するかどうかでは決まらない。振る舞いの中で目的、提供責任、判断権限を担うならアクターである。結果によって守るべき利害を持つなら利害関係者である。成功時に誰が何を得るかだけでなく、拒否や失敗のときにも誰の何を失わせてはならないかを問う。利害が衝突するなら、優先基準と最終的な判断責任者まで明らかにする。

## 例・反例・境界から確かめる

経費精算では、申請者が「正当な立替を精算する」という目的を持つ主アクターである。上長は承認判断を提供し、会計サービスは支払情報を提供する支援アクターになり得る。

会社には不正支出を防ぐという利害があり、申請者には理由のない不払いを避けるという利害がある。監査担当者は画面を直接操作しなくても、後から判断根拠を追えることへ関心を持つ。この利害を明示すると、単に「承認できる」だけでなく、拒否理由と証跡を残す必要が見える。

上長が自分の経費を申請するとき、その人は申請者として振る舞い、同じ申請の承認者にはなれない。人は同じでも、目的、権限、守るべき利害が変わる境界で役割を分ける。反対に、通知を受け取るだけで判断も提供責任も持たない仕組みは、相互作用に登場しても業務上のアクターにはしない。

## この概念の限界

- 個人名や部署名をそのままアクターにしない。役割と目的を言える粒度にする。
- 支援アクターを実装部品の一覧にしない。業務上必要な提供責任を見る。
- 声の大きい関係者だけを利害関係者にしない。直接操作しない当事者も調べる。
- アクター一覧だけで相互作用の内容や保証を決めたことにはならない。

別の業務シナリオで同じ役割名を使ったときに目的や権限が変わるなら、一覧へ例外を足すのではなく役割の境界を見直す。
