# bdd-discovery-and-formulation の eval

6つの公開入口はすべて最初の工程で `grill` を `playbook:` で呼び、利用者との対話で題材の曖昧さを解消してから正本を書く。`claude -p`（対話なし・tool無し）の1往復では対話と保存を観測できないので、自動実行は行わず手動evalを記録する。`scenarios.json` は agent が読む会話fixtureであり、自動採点の入力ではない。

## 手動evalの手順（代表1本: `discover-domain`）

| 項目 | 内容 |
|---|---|
| 実施者 | 利用者役1名（Claude Code または Codex の実セッションで `discover-domain` を呼ぶ） |
| 入力 | 依頼文「会議室予約の取消ルールをBDD付きで整理して」。追加資料は渡さない（`references` 無し）。保存先は既存の書き込める一時directoryの絶対pathと `.md` 名 |
| 利用者の発言 | grillの問いに対し、取消期限は「出荷日基準」、取消できる役割は「予約者本人と受付担当」と答え、それ以外の問いは推奨のまま受け入れる。最後に一覧へ合意する |
| 観測1 | 問いが成果を左右する順に出て、6問以下で、超過分は推奨を仮置きした未決として提示される（作法の本文は grill のものであり、この入口が独自の対話規律を持ち出さない） |
| 観測2 | 合意後にだけ正本が保存され、保存前に「保存した」と述べない |
| 観測3 | 正本の domain-rule に、利用者の発言と合意にない業務用語・役割・決まりが事実として書かれていない。仮説と未決は区別されて `## 未決` に推奨付きで載る |
| 観測4 | `scenario_matrix.py` / `actor-coverage.py` の検査結果が報告に出て、失敗を成功扱いしていない |
| 記録 | 会話の全文、保存された正本、観測1〜4の根拠箇所の引用を `evals/runs/<YYYY-MM-DD>/discover-domain-manual.md` に保存する。観測できなかった項目は「未観測」と書き、合否にしない |
