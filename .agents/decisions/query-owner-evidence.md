# クエリデータモデル検査における持ち主の構造証拠

## 決定

クエリデータモデルが指す持ち主に現行の五列分類表があれば、その表を従来どおり唯一の所有宣言として読む。五列分類表がない既存資料では、`論理テーブル` 欄を持つ表の対象行、対象名で始まる定義見出し、同名の `erDiagram` 実体がそろう場合だけ、構造上の所有宣言として読む。図にある属性名と Before の列名は、所有を認めた後に照合する。

五列分類表に対象名がない場合は違反とする。五列分類表がなく、異形式の三つの証拠もそろわない場合は、持ち主ではないと断定せず未確認として報告する。リンク先が業務上の真の持ち主か、読み取りが実現できるかは資料を読んで評価する。

## 理由

現在のコマンドデータモデルの型は五列分類表を検査目印とする。一方、完成済みのアカウントとポストのデータモデルは別の列構成の表、定義見出し、図でテーブルを定義している。五列見出しの完全一致だけを所有の条件にすると、正しいリンクを拒む。図の実体だけを条件にすると、持ち主の資料が参照用に描いたテーブルまで受け入れる。三つの構造を合わせれば今回の形式差を扱いつつ、単なる参照を所有宣言と取り違える範囲を狭められる。

## 確かめる境界

現行五列形式の正例と、分類表にはない図の実体を拒む反例を保つ。異形式の完成済み資料を読む正例、列の欠落、表・見出し・図のいずれかが欠ける例、対象名に似た別名、判定できない異形式を未確認にする例を検査する。`check` と `check-set` で未確認の扱いを揃える。
